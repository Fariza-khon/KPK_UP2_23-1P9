# Вариант №17. Room Service (Сервис аудиторий)

## Функции сервиса

1. Создание типа аудитории.
2. Создание аудитории.
3. Привязка аудитории к типу.
4. Получение информации об аудитории по ID.
5. Получение списка аудиторий по фильтрам.
6. Обновление информации об аудитории.
7. Удаление аудитории.

**Важно:** поле `is_active` используется только в **Room Service**. Для сервисов Auth Service, Profile Service, Role Service, Permission Service это поле не применяется.

## Таблица `rooms` (Аудитории)

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|--------|----------|--------------|------|-------------|--------------------|

| `room_number` | Номер аудитории | Да | `VARCHAR(20)` | Уникальное значение в комбинации с `building` | — |

## Таблица `room_types` (Типы аудиторий)

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|--------|----------|--------------|------|-------------|--------------------|
| `id` | Уникальный идентификатор типа аудитории | Нет | `INT` или `SERIAL` | **PRIMARY KEY** | Автоматически |
| `type_name` | Название типа аудитории | Да | `VARCHAR(50)` | **UNIQUE** (не допускает дублирования названий) | — |

## Таблица `room_room_type` (Связь аудиторий и типов)

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|--------|----------|--------------|------|-------------|--------------------|
| `room_id` | Ссылка на аудиторию | Да | `INT` | **FOREIGN KEY** → `rooms.id`<br>**ON DELETE CASCADE**<br>**NOT NULL** | — |
| `room_type_id` | Ссылка на тип аудитории | Да | `INT` | **FOREIGN KEY** → `room_types.id`<br>**ON DELETE CASCADE**<br>**NOT NULL** | — |

**Составной PRIMARY KEY:** (`room_id`, `room_type_id`) — гарантирует уникальность каждой пары «аудитория‑тип».

**Индексы для оптимизации:**
* `INDEX idx_room_id (room_id)` — для ускорения запросов по аудитории;
* `INDEX idx_room_type_id (room_type_id)` — для ускорения запросов по типу аудитории.

### 1. Добавить аудиторию (POST /rooms/)

**Информация для создания:**

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|--------|----------|--------------|------|-------------|--------------------|
| `room_number` | Номер аудитории | Да | string | Уникальное значение | — |
| `floor` | Этаж расположения | Да | integer | ≥ 1 | — |
| `building` | Корпус | Да | string | — | — |
| `capacity` | Вместимость (кол‑во мест) | Да | integer | > 0 | — |
| `type_ids` | Список ID типов аудитории | Нет | array of integers | Должны существовать в RoomTypes | `[]` |

**Примечание:** поле `is_active` не передаётся при создании — оно автоматически устанавливается в `true`.

**Уникальные комбинации:** `room_number + building` должны быть уникальными.

**Ответ при успешном создании:**

| Параметр | Тип | Пояснение |
|--------|------|----------|
| `id` | integer | Уникальный идентификатор |
| `room_number` | string | Номер аудитории |
| `floor` | integer | Этаж |
| `building` | string | Корпус |
| `capacity` | integer | Вместимость |
| `is_active` | boolean | Статус активности аудитории (`true` — активна, `false` — неактивна) |
| `types` | array of RoomTypeResponse | Типы аудитории |

### 2. Изменить аудиторию по ID (PUT /rooms/{room_id})

**Информация для изменения:**

| Параметр | Пояснение | Обязательность | Тип | Ограничение | Значение по умолчанию |
|--------|----------|--------------|------|-------------|--------------------|
| `room_number` | Новый номер аудитории | Нет | string | Если указан, должен быть уникальным | — |
| `floor` | Новый этаж | Нет | integer | ≥ 1 | — |
| `building` | Новый корпус | Нет | string | — | — |
| `capacity` | Новая вместимость | Нет | integer | > 0 | — |
| `type_ids` | Новые ID типов | Нет | array of integers | Должны существовать в RoomTypes | — |
| `is_active` | Статус активности | Нет | boolean | — | Сохраняется текущее значение |

**Ответ при успешном изменении:** аналогичен ответу при создании, включая актуальное значение поля `is_active`.

### 3. Удаление аудитории по ID (DELETE /rooms/{room_id})


**Реализация:** мягкое удаление (soft delete) через установку флага `is_active = false` (запись остаётся в БД).

**Логика операции:**
1. Находим аудиторию по `room_id`.
2. Устанавливаем `is_active = false`.
3. Сохраняем изменения в БД.
4. Возвращаем результат операции.

**Условия:**
* если аудитория уже неактивна (`is_active = false`), возвращается `false`;
* если аудитория найдена и успешно деактивирована, возвращается `true`.

**Ответ:** `boolean` (`true` — аудитория деактивирована, `false` — не найдено или уже неактивна).

**Параметры фильтрации:**

| Параметр | Пояснение | Тип | Описание |
|--------|----------|------|--------|
| `building` | Фильтр по корпусу | string | Возвращает аудитории только указанного корпуса |
| `floor` | Фильтр по этажу | integer | Возвращает аудитории только указанного этажа |
| `min_capacity` | Минимальная вместимость | integer | Возвращает аудитории с вместимостью ≥ указанному значению |
| `type_id` | Фильтр по типу аудитории | integer | Возвращает аудитории указанного типа |
| `is_active` | Фильтр по статусу активности | boolean | `true` — только активные, `false` — только неактивные, отсутствует — все аудитории |

**Ответ в виде списка аудиторий:**

|--------|------|----------|

| `floor` | integer | Этаж |
| `building` | string | Корпус |
| `capacity` | integer | Вместимость |
| `is_active` | boolean | Статус активности аудитории |
